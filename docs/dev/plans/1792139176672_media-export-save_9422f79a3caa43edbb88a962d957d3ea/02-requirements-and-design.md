# 需求与设计

1. 用真实编码器及浏览器文件流复现保存流程，分别验证准备、逐帧编码、封装和落盘；不把正常编码期间尚未提交的临时空文件误判为成功。
2. 进度与取消入口在桌面、窄屏以及高级设置展开时保持可见；未知总量阶段显示不定进度，编码显示帧数，封装和提交完成后才报告成功。
3. 输出失败或取消必须向用户报告；文件流事务由单一所有者管理，保留已有目标文件，不因编码器的取消清理提交半成品；空输出不能报成功。
4. 保持流式背压及位置写入，避免退化为整段影片内存 Blob。保留不支持文件选择器时的下载路径。
5. 补充节点测试和隔离浏览器验证：MP4/WebM、带声音/无声音、空输出、写入错误、取消、重试、Blob 下载、本地文件流提交及窄屏进度。仅本地测试，无外部供应商请求。

实施后在此目录记录实际原因、复现证据、验证结果和未覆盖项；更新中英文媒体导出契约。若缺少用户 JSON，不声称已重现其具体场景。

## 收到样例后的补充范围

- 用户提供 150 秒、8 镜头的相对论 JSON，要求区分制作暂停与导出失败；原样保存为测试夹具，不把 paused 状态作为导出禁令。
- 实际配乐只有约 66.75 秒。保持音频模块的严格时长检查，宿主提供显式循环/补静音选择，仅作用于本次预览/导出。
- 导出先检查所选范围内各镜头的资源与时间线，并返回镜头 ID；只做首帧可执行性检查，不冒充整片视觉验收。失败不打开文件写入事务。
- 用户追加“少量汉字显示方块，是否编码问题”。用原始场景、有/无点云及可用中文字体做画面对照，不凭截图认定编码错误。点云顶层 size 的兼容读取保留 material.size 优先和历史默认值，不引入 ThreeBox 专属规则。
- 禁止执行生成 JSON 中任意 geometry.func JavaScript。样例若需修复，只在独立副本中转换已知表达式并记录差异；不修改原夹具或伪造制作完成状态。
- 完整影片测试新增复现：组内 SDF 文字暂存容器迁移触发 removed，被当成销毁/AbortError。区分同步重挂载与真正移除，保留真实取消和销毁的清理；媒体边界仅在调用方 signal 确实取消时传播取消，否则给出镜头失败而非静默取消。
