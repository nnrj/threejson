# 需求、设计与验收

## 设计

1. 新增 `release:preflight`：读取 npm 目标版本并检查可复用包，不执行发布、全量测试或版本升级；一键流程在版本同步后、测试与全量打包前执行相同检查。
2. 完整 tarball integrity 相同则快速通过；不同时，先询问是否执行可选的逐文件对比及差异报告，提供 `--compare-files` / `--no-compare-files` 参数。跳过时不下载/解包远端资产，摘要不同应报告无法确认而非断言资源变化。获准后使用工具层开发依赖 `tar` 流式读取包内文件，比较路径、原始字节摘要及可执行权限，忽略容器时间戳、压缩和条目顺序差异。不提取远端 tarball 到文件系统；下载须匹配 registry integrity，异常/不支持条目按失败处理。
3. 真正差异列出新增、删除、修改的路径；不能通过 `--resume` 绕过。仅容器不同且文件逐字节一致时允许复用已经发布的包，不覆盖 npm 版本。发布与 Git tag 共用此验收标准。
4. 保持独立 `release:pack` 的离线全包打包语义。一键流程跳过已验证复用包的正式 tarball 输出；校验仍可能临时打包。发布前再次验证，避免测试或外部操作改变资源后沿用旧判断。
5. `release:version --only-assets` 只升级 assets 并同步引用，保留主包、组件版本；给出不重跑 `release:all` 的继续流程。
6. 保留根目录现有用户版本变更，只添加发布所需开发依赖和对应锁条目。版本文件无变化时不重写。

## 风险与边界

- 不以文件时间、文件大小、Git 干净或 npm 文本 diff 代替二进制内容验证。
- JSON 空白和文本换行属于文件字节变化，不自动归一化；二进制变化、文件删除、执行权限变化均不可忽略。
- 不依赖 npm 私有模块或操作系统 tar 命令；归档解析只在 Node 发布工具中使用，不进入引擎运行时。
- 远端下载有超时，归档错误、重复/危险路径和链接不静默跳过。临时目录由工具创建并仅清理自身内容。
- `release:preflight` 是联网检查而非认证/实际发布成功证明；无网络应报无法验证，不冒充资源不变。

## 验收

- 同内容不同容器允许复用；真实二进制/文本/文件集合/执行权限变化拒绝，显示差异路径。
- integrity 验证失败、无效 tar、危险路径、重复路径、链接失败关闭。
- 一键流程在测试与全包打包前完成检查；未变 assets 不生成正式发布 tarball；独立 pack 仍可离线执行。
- assets-only 版本操作保留主包与组件版本；读取预检不升级用户版本，不执行发布。
- 使用用户已有本地 assets tarball 与 npm 1.1.6 做真实只读比较，记录文件级差异；单测使用合成归档/依赖注入，无 npm 写入。
- 检查相关回归及 `git diff --check`。不将本地测试等同于实际 npm 发布或线上部署验证。

## 回滚

仅撤销本次工具、测试、文档及新增开发依赖；保留用户原有版本同步改动和历史 tarball，无线上迁移。
