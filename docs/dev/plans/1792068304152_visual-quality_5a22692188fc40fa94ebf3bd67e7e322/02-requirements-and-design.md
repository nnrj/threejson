# 实现设计与验收边界

质量能力位于 `threejson/visual-quality`，由宿主注入观察、评审和修正适配器。内核只提供可组合能力，应用不得把辅助灯或播放后的相机状态保存为已评审源文档。共享包和静态宿主之间由 `syncHostSessionModules.mjs` 同步有限模块，保留各自资源路径配置。

新 `look.apply/material.recipe/camera.frame` 操作进入现有事务与撤销服务，不引入平行编辑状态。质量报告绑定 SHA-256 文档版本；下一次修改、纹理完善或重开校验不匹配即失效。无法运行渲染检查时保留作品但不通过最终质量门槛；原来的供应商/命令失败原因优先保留。

模型资产策略位于创作入口，覆盖普通输出、命令、Patch 和流式预览。模型服务是来源/许可证/下载和持久化的可信边界，不允许模型自行生成外部 URL 绕过。新获取使用自包含 glTF/GLB 副本，使现有资源打包器无需解析未知依赖图；不删除源参数，也不把引用资产当作原创建模。

重点风险：有限采样不能证明全帧/全网格正确；闭合拓扑不能证明工业可制造；低调照明不是错误；未知费用不能保证绝对账单上限；受信任目录也需要运营方核实许可和 DNS；Cloud 必须发布并升级真实依赖，不能把本地包构建通过当作线上已部署。

设备预览策略与创作、导出独立：按设备提示选择像素/Points 绘制预算和已有 LOD 偏置，允许手动选择。帧后恢复源状态，失败也恢复；完整检查与导出不得复用降档预览。实例化 billboard、任意网格重建和全部模拟内存自适应不在此保守绘制预算内。

详细覆盖点、命令、部署次序、未完成的真实供应商/设备验收以及回退策略统一见 [实施与验收](../../visual-quality-verification.md)。
