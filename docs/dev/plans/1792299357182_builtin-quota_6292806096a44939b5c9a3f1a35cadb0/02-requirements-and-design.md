# 需求与设计

## 契约与边界

- 内置设备额度继续要求轮数、金额同时未耗尽；GET quota 和 429 使用同一快照函数，暴露两类用量、上限、剩余值与 exhausted 原因。保留 QUOTA_EXCEEDED 错误码兼容旧客户端。
- 宿主同时展示轮数和金额（明确 USD），保留精度；缺少金额字段显示未知，不伪装成零余额。旧缓存标记待刷新或刷新失败。识别 ID 优先采用服务端实际凭证绑定的 ID。
- 通用 ThreeJSON core 不包含额度、管理员权限或产品 UI。ThreeJSON 的多个宿主复用 host-kit 展示函数。Cloud 保持独立发布兼容，不改变已有账户积分制。
- 后台增加单设备“充值金额额度”：正数金额换算为 USD cents 后原子累加 cost_limit_usd_cents，不改 rounds_limit/rounds_used/cost_used_usd_cents。复用管理员会话和权限边界。
- 充值携带幂等键；复用审计表主键在同一 D1 batch 中写入充值凭证和更新上限，重复请求不重复加额，金额不一致拒绝。避免读旧余额再覆盖上限造成并发丢失。
- 不接入支付收款，不把额度调整等同于已收到真实货币。后台明确这只是管理员授予的调用金额额度。

## 验证与回滚

- 服务端：轮数耗尽、金额耗尽、同时耗尽、都有余额；GET 与错误快照一致；充值后可以继续调用；正数/类型校验、未登录/只读权限拒绝、重复充值、并发充值及用量不变、审计记录。
- 前端：双额度、极小金额、缺失字段、Cloud 账户次数、中文/英文错误提示；原生/React/编辑器接线与 Cloud 类型检查。
- 构建后台与受影响前端；本地隔离测试不访问生产或付费服务。
- 手动验收：窄屏可读；金额耗尽时仍显示剩余轮数并明确金额原因；管理员充值后刷新可见；断网显示缓存标记；重复点击不重复充值。
- 回滚代码即可，新增字段向后兼容，不需要数据库迁移。已授予的额度及审计记录保留，不自动撤销。

## 实施结果

- 已实现：设备双额度快照及明确超限原因；原生 ThreeBox、React ThreeBox、场景编辑器与 Cloud 兼容界面的双额度/缓存状态展示；后台单设备金额充值（owner 权限、原子累加、幂等审计）。Cloud 的登录账户仍显示调用积分，不换算成金额。
- ThreeJSON：36 项测试通过（双额度展示、错误反馈、隐私、宿主模块一致性及依赖边界）。共享展示模块及声明加入既有同步校验；Cloud 独立发布兼容副本由离线跨项目回归核对完全一致。
- threebox-server：23 项测试通过（新增 7 项额度/充值回归，现有聊天、管理鉴权、设备检索及 Cloud 积分）；类型检查通过。
- 后台与 React ThreeBox 生产构建通过。Cloud 类型检查通过；直接构建暴露既有已安装 host-kit 缺少 creationQualityPolicy.js，未改动真实 node_modules / 锁文件。用 `verify-cloud-local-packages.mjs` 隔离本地包构建通过，记录位于 `dist/cloud-local-packages-OnUnS8`；这不能替代正式依赖发布与部署验证。
- `node tools/dev/verify-builtin-quota-ui.mjs`：本地 Edge 无头浏览器通过桌面/360px 窄屏显示、断网缓存标记、CNY→USD cents 转换、响应丢失后沿用幂等键重试的实际 UI 回归。测试账号、额度、充值均为内存模拟；所有外部请求被拦截。截图位于 `dist/builtin-quota-ui/`。
- 无数据库迁移；未修改线上账号、调用付费模型、提交或部署。生产部署、真实账号与实体移动设备验证不在上述自动测试结论内。
