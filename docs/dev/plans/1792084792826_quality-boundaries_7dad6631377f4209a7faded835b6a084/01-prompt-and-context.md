# 生成质量能力的架构边界修复

## 人类评审

- 评审人：本会话项目维护者（用户）。
- 日期：2026-10-16，Asia/Shanghai。
- 结论：通过。用户先同意移除 Core 固定几何上限及服务 URL 特判；随后讨论设备适配、质量报告归属，并以“好的，同意你的建议”确认全部方案。

## 已确认决策

1. Core 提供通用能力，不写死特定应用的资源限额；需要的限额由宿主明确传入。
2. 场景包通过中性必需资源契约执行严格打包，服务 URL 识别留在宿主。
3. Core 提供可恢复的预览预算执行机制，默认不降质；官方共享宿主模块提供可配置设备/帧耗时策略，ThreeBox 默认自动适配，其他调用方可关闭。内容相关 LOD/粒子降级须明确允许；导出不继承降级。
4. 通用结构化质量报告、版本校验及可选 AI 评审流程保留在 ThreeJSON；产品档位、供应商决策和多语言展示上移共享宿主层。
5. 澄清显式宿主启用与描述符启用、显式视觉配方与运行时隐式默认值的区别，不削弱单向依赖原则。

本轮修改建立在已有未提交的视觉质量实现上，不回退其他工作，不推送、发布、部署或调用付费供应商。
