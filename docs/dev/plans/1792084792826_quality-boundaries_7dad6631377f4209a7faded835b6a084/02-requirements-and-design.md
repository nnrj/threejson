# 需求、设计与验收

## 实施顺序

1. 几何：删除固定 2M/256 上限，保留数值/分配合法性校验。预算前置于采样/分配，并在输出时复核；传入预算不被描述符覆盖。误差细分不静默声称已达到未满足的精度。
2. 导出：Core 支持必需资源回调/列表；宿主模型适配器负责服务地址规则，全部相关场景包入口共享策略。
3. 预览：Core 仅接受数值预算或注入的控制器，未启用不创建状态。共享模块提供预设、反馈控制和恢复逻辑；原生/包版及媒体预览同步，正式导出禁用预览预算。
4. 评审：Core 接受明确评审配置，不绑定四档产品名称；保留报告版本、检查状态、范围、证据与修正事务。共享层保留四档默认值和中英文格式化，迁移所有调用点与类型定义。
5. 更新中英文契约、架构回归测试及原生/发布共享文件；重建几何 worker，执行针对性及完整测试和应用构建。

## 验收与风险

- 默认 Core 无任意资源额度、服务地址识别、产品报告排版或设备分档。
- 显式预算在大量分配前失败，错误可诊断；主线程/worker 行为一致。
- 预览降级可恢复且不改源文档；未明确允许不抽样粒子/偏移 LOD。反馈带滞回，不因暂停或后台间隔误降级。
- 缺失必需资源严格失败与 URL 无关；历史模型依然可打包。
- 未检查、不可用、结构通过和采样视觉通过明确分开；修改作品后旧报告失效。
- 原生共享源与 npm host-kit 镜像一致；没有 Core 到宿主的反向导入。
- 采用本地模拟与自动化验证，不把测试通过表述为供应商、线上或真实移动设备验收。

## 回滚

按本方案相关文件回退，不回滚先前视觉质量修复；保留作者 JSON 与既有项目。公共接口为 alpha 调整，同步全部仓内调用方并记录发布依赖顺序。
