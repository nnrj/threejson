# ThreeJSON 时间线、程序化视频与可选音频能力实施计划

更新：2026-09-29。本文整合已确认的时间线、动态片段、音频、媒体导出与模型管理方案；实施证据另见 `02-implementation.md`。

## 1. 目标与边界

- 主线是确定性回放、完整单场景动画、多片段编排、声音、音乐，以及图片/GIF/视频导出。保留 ThreeJSON 的建模、交互、事件、编辑、撤销与资源能力。
- 单个 JSON 或 `.tjz` 可以独立描述完整视频，包括复杂场景、粒子、算子、运镜、音轨、字幕、镜头和转场。多文件机制不能成为高级表达能力的前提。
- 多个场景可组成动态片段（协议名 `clip`，不是输出帧 `frame`）。片段可以有自己的完整时间线；同一场景可重复引用、裁剪、变速。片段没有人为时长上限。
- 不新增 `.tjzs` 或 `.tj`。继续使用 JSON / `.tjz`，通过显式文档类型及归档入口类型区分 scene、object、composition。旧场景继续按场景加载；不认识的类型明确报错，不退化为立方体。
- 三种组织方式（内嵌、外部场景引用、便携打包）共用语义。总编排不复制另一份场景真源；采用现有不可变文档、稳定 ID、SceneSession、操作注册表、撤销和 job 协议。
- 媒体反向重建是锦上添花：一期只提供独立的媒体准备/分析结果契约和可注入接口，不为它重构核心；完整视频理解、供应商接入与重建工作流安排二期。
- 不接入云端渲染农场，不建设完整 NLE/DAW，不把 TTS 冒充自然演唱。无运营后台、数据库或云存储变更作为本地制作的前提。

## 2. 引擎时间与作品编排

- 引入显式场景时间，支持 play/pause/reset/seek/evaluateAt、倍速和指定时刻渲染。导出逐帧求值，不录制 RAF 的实际运行速度。
- 变换、路径、morph、颜色、透明度、材质参数、相机等按绝对时间求值；有状态粒子采用固定步长重放，默认 1/60 秒，可配置且不依赖导出 fps。后退恢复初始状态或检查点。
- 动画结果属于运行时，不逐帧写回 JSON 或增加撤销记录。手动编辑仍通过原有事务接口。
- 旧动画、AnimationMixer、shader、GIF/视频贴图接入同一时间；不能确定性重放的扩展或外部副作用报告具体诊断，不假装已经验证。不因 seek 重复联网、播放通知或其他业务事件。
- 时间线使用稳定 ID，支持对象变换/显隐/材质/morph、相机位置/目标/FOV、音频、字幕及镜头片段。相机可使用既有路径与缓动。
- composition 的全局时间映射到各 clip 的源时间；从源场景第 10 秒开始的片段必须恢复第 10 秒状态，而非从零重新模拟五秒。
- 同一世界的连续镜头可以共享场景时间，只切换相机；独立片段隔离可变状态。同一个渲染器可顺序渲染相容片段，交叉溶解使用必要离屏目标，不为每个文件永久创建一个上下文。
- 支持切换、淡入淡出、交叉溶解。全局音乐不因片段切换重启；画面与音频转场分别编排。
- 资源解码、文字排版及 GPU 初始化完成后才采集输出帧。预加载下一片段，失败保留诊断，不输出黑画面后声称成功。
- `.tjz` 扩展为共用容器：composition.json、scenes 与 assets。资源内容去重，使用稳定 pack 引用；大型资源按二进制保存，不为多场景归档新增整包 Base64 中间态。异步归档/索引与按需访问逐步替换同步全量处理路径，不承诺 HTTP 不支持 Range 时仍可无需下载整个包。

## 3. 粒子与视觉

- 粒子源沿用文字、图片、曲线、meshSurface；加入稳定采样、聚散/波动/旋涡/轨道、目标点云之间的变形，以及时间/音频信号驱动。
- 固定 seed 后同环境可复现。不同点数通过确定性映射与显隐过渡处理，不静默削减场景要求的粒子数。
- 内置算子可参数化调用；可选注册表接受自定义算子。CPU 为参考实现，GPU 后端明确声明支持的能力，不自动忽略不支持的参数。
- 去除生命周期曲线统一固定 8 个关键点的表达限制；GPU 使用合适的数据表示，硬件限制具体报告。
- 普通 3D 场景、2D 正交构图、3D/屏幕文字、字幕和数据图表都可制作图片或视频；不要求所有内容都粒子化。
- 未启用的 raster、GPU、媒体编解码和模型能力不进入普通立方体的默认加载路径。

## 4. 声音、音乐和可选模型

- 声音通过同一资源机制接受 URL、本地文件、乐谱合成、TTS 及宿主音频生产器；支持裁剪、循环、淡入淡出、音量/声像和离线混音。音频真实时长参与编排，锁定片段冲突时报告，不偷偷截断或加速。
- 新建可选 `@threejson/audio-kit`：中立乐谱数据、校验、演奏编译、电子合成、音源接口、PCM/WAV 及混音。参考 PoemHaven 的音符/小节/声部/反复/连音/速度/力度/歌词机制与分段 AI 谱曲，不引入其论坛、配额或 Java 后端。
- 乐谱以音乐时间为真源，支持可配置 PPQ。业务上限不搬入引擎；缓存包含乐谱、音源和合成配置哈希。MIDI/MusicXML 交换和 SoundFont 为可选能力。
- 电子合成为无需大文件的基础选项；用户可导入 SoundFont 使用采样音源。试听与离线合成使用同一个演奏计划。
- TTS 通过独立适配器接入；首批目标为 MeloTTS 中英及 Kokoro 中英。模型目录中的可用项必须经过真实加载验证，不能以空实现或 mock 声称支持。
- 浏览器系统朗读仅作试听能力，不冒充可导出的音频。原生视频、商业语音及演唱供应商由宿主接入，core 不新增厂商依赖。
- TTS 模型不在 threejson、默认 assets 或 npm postinstall 中下载。普通场景、无旁白视频不需要它。
- 模型 SDK 负责清单（ID、版本、适配器、文件角色、大小、hash、许可）、download/import/status/remove/acquire、进度、取消和完整性校验；宿主只做配置与 UI。
- 网页大型文件优先 OPFS、索引用 IndexedDB，缺少 OPFS 时使用 IndexedDB。缓存按 origin 隔离，可查询额度与申请持久化；不保证浏览器永不清理。
- CLI 使用用户缓存目录（Windows: `%LOCALAPPDATA%/ThreeJSON/Cache/audio-models`）。调用参数/命令行 > `--config` 文件 > 默认值；配置相对路径相对于配置文件。不强制新增 threejson.json。
- package.json 只配置可选软件依赖，不能用它指定终端用户机器的模型位置。浏览器本地导入需用户选文件，SDK 保存副本；不假设任意 ONNX 都兼容。
- 模型权重是工具依赖，不随作品自动打包；生成音频是作品资源，可随 `.tjz` 分享。保存生成配方用于重做，但接收方播放已生成音频不需要模型。
- 合成放到 Worker 中；单线程 WASM 为兼容基线，不为 TTS 强制全站开启跨源隔离。模型、运行库及音色许可分别记录。

## 5. 正向媒体导出与反向扩展

- 将此前计划的 video-kit 扩展为可选 `@threejson/media-kit`，统一图片、GIF、视频，不建立平行的三套渲染器。
- 公共能力：`renderImage`（指定时刻 PNG/JPEG/WebP）、`renderGif`（时间范围、帧率、循环、调色板）、`renderVideo`（MP4/WebM、音轨）、媒体能力发现、作业进度/取消。输入接受场景/编排对象、JSON 文件和 `.tjz`。
- 正向转换不需要 AI。共享 prepare -> evaluate(time) -> render -> encode 流程，默认 MP4/H.264/AAC、1080p/30fps；先检测实际编码能力，替代格式需要明确选择，不改扩展名冒充格式。
- 浏览器使用 WebCodecs/Mediabunny；GIF 编码器按需加载到 Worker。GIF 无音轨且有调色板/透明度限制，UI 明示；图片默认为 PNG，可指定透明背景，不强行叠加宿主主题色。
- 原有 MediaRecorder 保留为明确的实时录制用途；程序化导出不依赖它。编码交错提交音视频，流式写入支持文件偏移与背压，不将整个作品帧序列长期驻留内存。
- CLI/MCP 扩展现有 scene-tools：使用已安装浏览器确定性渲染，可选已安装 FFmpeg；不自动安装系统程序，不覆盖已有输出。
- 一期媒体反向扩展只提供媒体准备接口、带时间戳的帧/资源引用和分析结果契约；不隐藏调用真实模型、不伪造重建成功。现有图片生成保持可用。
- 二期上层可选择直接让多模态模型生成，或视觉分析后交给现有场景 Agent。同一个 Agent 可以多轮读取参考、建模与验证，不强制两次模型请求。
- 宿主/适配器提供 inputModalities、传输方式与真实限制；通用 Agent 编排根据声明协商。具体上传、认证、视频 URL/file-id 等厂商协议不进入 ThreeJSON core。未知能力不能根据品牌猜测。
- 分析结果允许普通文字或结构化镜头/实体/布局/运动/不确定信息，保留原始用户要求与时间戳。静态图是一帧参考；GIF 为正确合成 disposal 的带时序参考。
- 反向能力称为“AI 重建”，不承诺精确逆变换，不以原视频贴片冒充可编辑三维重建。它不阻塞主线发布。

## 6. Agent、应用与交付

- 原场景生成/调整 Agent 增加时间线、视频和音乐能力模块，使用现有操作发现、事务、版本和 jobs，不另建历史系统。生成目标支持 scene/image/gif/video，语义判断后允许手动覆盖。
- ThreeBox：作品预览/播放/定位、片段列表、基础时间线、音轨控制、导出选项、模型管理；沿公共 packages 同步原生/React 宿主。移动端分区面板；历史作品不可变，默认单个预览发声。
- Editor：基本时间线数据及片段检查/编辑进入统一撤销事务，不扩张为专业 NLE。Player/Shower 能播放与导出作品，缺少能力要说明，不破坏现有普通场景。
- threebox-cloud 复用公共能力；本地创作/下载不要求 R2 或登录。threebox-server/dashboard 的原生视频供应商配置属于二期，不因附加重建需求扩大一期后端范围。
- 官网与 html-demo 提供：粒子文字/图案变形、模型运镜、图表、配乐律动、旁白字幕、多片段转场；提供不依赖 TTS 下载的基础示例。
- 更新双语文档、包导出、类型与发布脚本。可做本地提交；不 push、publish、部署、不调用付费模型。

## 7. 验收与实施顺序

1. 更新本计划并记录基线；确定时间控制与回放。
2. 时间线、动态片段、粒子与媒体纹理确定性。
3. 音频/乐谱/合成与可选模型 SDK。
4. 图片/GIF/视频导出、CLI/MCP、应用与 AI 能力接入。
5. 示例、文档、集成回归和未覆盖项清单；反向重建不阻塞前四项。

必测：

- 顺序求值、随机 seek、后退重放得到相同时间的正确状态；30/60fps 不改变运动或音乐速度。
- 内嵌、多文件、`.tjz` 的相同作品输出一致；重复引用同一场景时可变状态隔离，修改不污染历史。
- 音画同步、变速/裁剪、跨片段音乐、转场；GIF 时长/disposal/透明度，图片实际 MIME 与透明背景。
- 资源未就绪/CORS/字体失败/编码器缺失/取消/上下文丢失可诊断并释放资源，不能用黑帧冒充成功。
- 乐谱反复、连音、变速、音源、声部；真实本地 TTS 下载/导入/加载另行标记，不以 mock 替代音质验证。
- 模型中断/损坏/额度不足/缓存清理；分享带音频作品不需要模型。
- 一分钟 1080p 导出及长音频内存行为；引擎无固定时长、模型数量和 AI 轮数限制。
- room-show、port-show、现有 html-demo、Editor 撤销和多画布；普通立方体不加载媒体编码器、TTS/音乐库或额外模型网络请求。
- Node、真实浏览器、包边界、类型、发布状态；记录实际验证与尚未验证项目，不夸大跨设备或音质保证。
