# 视频续作的镜头命令契约与恢复

## 用户反馈与授权

2026-10-18：用户在 ThreeBox 点击“继续制作视频”后，8/8 镜头的 150 秒视频再次因
`repeated_operations` 暂停，错误详情为 `Shot query accepts only read operations.`。
本轮沿用用户要求核查修复的授权；不调用付费供应商，不修改线上账户，不部署或推送。

## 已确认的源码与最小复现

- `media.shot.query/edit` 只暴露任意 object 数组，没有嵌套 SceneOperation 参数契约的发现入口。
- 未知的 `scene.inspect` 和确实写入的 `object.patch` 都返回同一句只读错误；合法的 `scene.query` 正常。
- Agent 再次给出同一失败调用时在执行前立即退出；失败回执没有具体命令、路径或修正方式。
- 续作只在提示词中要求读取存档，没有在首轮请求中可靠提供保存状态及上一次错误。

截图没有内部调用的原始参数，不能断言线上具体是哪一个子命令出错。修复覆盖未知命令、
误用读写入口、参数缺失和失败后的继续制作；不移除只读边界，不伪装视频已经完成。

## 约束

遵循 `docs/zh/design-principles.md`：Core 只提供通用 Agent 上下文与恢复机制；镜头契约属于
media-kit，中文提示属于共享宿主。源文档、音轨、时长和事务/撤销不被纠错提示修改。
不重做视频编辑器，不处理无关的模型/导出问题。
