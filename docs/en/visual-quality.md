# Generation quality and visual authoring

[中文](../zh/visual-quality.md)

`threejson/visual-quality` exposes read-only geometry/runtime observations, real frame capture, lighting/material/framing recipes and an injectable generation review loop. Authored JSON remains authoritative. Inspection lights are explicitly labeled and excluded from review and export.

The official **host policy** exposes `creationQuality`: `quick` (default), `standard`, `fine` or `ultimate`, with 0/1/2/3 proactive repair rounds. Quick performs local checks without a separate paid visual review. Higher tiers use declared image-input capabilities, multiple views and sampled video frames. Exhausting a repair budget is not success. Reports bind to a document hash and expire after edits. Missing requested image review or runtime inspection cannot pass the final gate. Profiles do not override provider, reasoning, preview resolution or user budgets.

Core's `runCreationQualityReview(document, {profile, inspect, review, repair, validate, ...})` is generic: `profile` contains `id/repairRounds/views/samplesPerShot/alternatives/reviewVisual`, with no product tier lookup or UI formatting. Omission requests no extra visual calls or repairs; visual review is independent from the repair count. Hosts may supply arbitrary budgets, including explicitly unbounded repair rounds with cancellation. `@threejson/host-kit/js/creationQualityPolicy.js` owns `resolveCreationQuality`, overridable tier presets and localized `formatQualityReport`. Reports include `checksComplete`, `coverage`, `messageCode` and English diagnostic messages, in addition to structural/visual status, issues and document revision. A failed visual check is not mislabeled as a structural failure.

`look.apply`, `material.recipe` and `camera.frame` are transactional document operations. Recipes expand into ordinary lights, materials and cameras. The local `{type:"studio"}` environment is a WebGL reflection source, not an external download. Intentional darkness and unlit diagrams remain valid artistic choices. Explicit shadow disablement and environment intensity/rotation round-trip through runtime configuration.

SDF surfaces use outward winding and smooth field-gradient normals. Closed loft/sweep seams preserve UV splits; caps retain hard normals. `smoothSeams:false` and `orientation:"profile"` preserve intentionally hard/oriented surfaces. `orientation:"inward"` requests interior faces. Surface `tessellation.maxError/maxSegments` provides bounded sampled chord-error refinement, not a global mathematical guarantee. Camera path signals opt into `parameterization:"arcLength"` with `easing` or an integrated `speedCurve`; legacy parameter timing stays the default.

Core has no fixed vertex/sample ceilings or hidden 256-segment clamp. Invalid/non-safe allocation sizes still fail. Explicit `meshBudget:{maxVertices,maxTriangles,maxBytes,maxSamples}` is checked before allocation and during implicit output growth. `geometry.userData.tessellation` records measured error, subdivisions and convergence when an authored `maxSegments` prevents further refinement. The browser host compiler defaults to 2,000,000 vertices and 2,097,152 implicit samples; `createSceneHostGeometryCompiler({meshBudget})` may override or disable these with `{}`. These are host safety policies, not engine expressiveness limits or a universal memory-safety guarantee.

AI external-model acquisition requires both server and personal switches. Existing models, explicit local imports, textures and environment maps are unaffected. Trusted adapters resolve `asset-model://search/<keywords>` or `asset-model://id/<id>` against licensed catalogs. The server stores self-contained glTF/GLB copies and provenance; these are referenced assets, not original generated modeling. Packaged-model download failures are explicit. Default sources are Poly Haven and administrator-managed HTTPS catalogs; follow their API and license requirements.

Core's preview-only `previewPerformance` accepts numeric budgets (`maxPixelRatio/maxPixels/maxPoints/lodBias`) or an injected `{getBudget,onFrame,resetFeedback}` policy. Omission, `false` or `"full"` performs no degradation or device probing. `@threejson/host-kit/js/previewPerformancePolicy.js` supplies `createHostPreviewPerformance("auto")`: device hints select an initial level, measured continuous frame times and hysteresis allow degradation **and recovery**. ThreeBox/video editor opt in by default; reusable card sessions default to full. Product names and tunable thresholds live only in the host.

Default host adaptation only scales pixels. `allowPointSampling:true` and `allowLod:true` separately authorize uniform Points sampling and existing LOD bias. Geometry/LOD state restores after each draw, including failures; full-quality recovery and disposal restore the requested renderer/composer DPR. Effects are retained, simulation time is never skipped, and no arbitrary mesh simplification occurs. Review and export always render independent full-quality projects. Exporting a reduced preview project directly fails with `PREVIEW_PROJECT_NOT_EXPORTABLE`; pass the source document instead. Device benchmarks remain necessary.

Archive core accepts generic `resolveAsset(ref)` and `requiredAssets`, `isAssetRequired({key,ref,path})` or `strictAssets:true` options. Missing required resources fail with `ARCHIVE_REQUIRED_ASSET_UNAVAILABLE` and `ref`; optional unresolved references remain external. Product URL recognition and download policy are injected by host `modelAssetResources.js`, never embedded in core.

See the [implementation and verification record](../dev/visual-quality-verification.md) for tests, migration 0025, package release dependencies, security limits and remaining real-provider/device validation. Local automated checks do not establish an average aesthetic score or film-quality output.
